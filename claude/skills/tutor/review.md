# Tutor の振り返り: 作業から話題を見つける

本人の最近の作業（開発ログ・PR）から、本人が作ったり使ったりしたのに、まだ説明できていなさそうな事柄を見つけ、学習 DB に話題として足す。

## 読むもの

- Notion の開発ログ DB の直近7日（URL は `~/.claude/notion-hub.local.md`）
- 開発ログの `リンク` にある PR の説明と差分（`gh pr view`・`gh pr diff`）
- 学習 DB の今ある話題（重複を除くため）

## 見つけるもの

- Claude が作って本人がマージしたが、仕組みや理由を本人が説明していなさそうなもの。例: 使用量の段階（eco）の決め方、サブエージェントに文脈を分ける理由、プロンプトのキャッシュ
- 作業の中で選んだやり方の、ほかの選択肢と違い
- 次に学ぶと、今の仕組みを伸ばせそうなもの

本人の仕事（受託・勤務先）の中身や、業務のデータは話題にしない。仕組みの話だけにする。

## 手順

1. 開発ログと PR を読み、上の「見つけるもの」の候補を挙げる。
2. 学習 DB の今ある話題と重なるものを除き、1回に3件まで選ぶ。
3. 学習 DB に1行ずつ足す。書き方は SKILL.md の「3. 学習 DB」。状態は「未読」、出どころは「振り返り」、出典は PR や開発ログの URL。
   - `## 本人の仕組みとの関係` に、どの作業で出てきたかを書く
   - `## 確かめる問い` を必ず書く
4. 足した話題を返す。

## 決まり

- Claude: 学習 DB の話題は、1回の応答で1件ずつ書く。1回の応答が、考える時間と書く時間を合わせて5分を超えると、プロンプトキャッシュが切れ、次の呼び出しで文脈の全部を作り直すことになるため（応答を分けて増える分は、それよりずっと小さい）。
- 今は対話で使う。自動開発から定期で動かすときの読み書きの仕方は、定期実行を作るときに足す。

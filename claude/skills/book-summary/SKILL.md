# 書籍要約

本を最後まで読み、**あとで判断や実践に使える要約**を作る。読み物としてのあらすじではなく、「この本は何を主張し、何をすればよいと言っているか」が出典ページつきで分かることを目指す。

作業は次の5段階で進める。

1. 下準備（読み方を決める）
2. 通読して章ノートを作る
3. 要約の初稿を書く
4. 自律レビューで収束させる
5. 仕上げて保存先に出す

本は長いので、途中の結果は必ずファイルに書き出しながら進める。コンテキストが要約・圧縮されても、ファイルが残っていれば続きから再開できる。

## 1. 下準備

### 要約する本を決める
引数や依頼文で PDF が指定されていれば、それを使う。

指定がなければ候補を探して提案する。探す場所は次のとおり。
- 今のディレクトリの配下（`references/`、`books/`、`docs/` などを優先）
- `~/Desktop`、`~/Downloads`（kindle-capture スキルの既定の保存先が `~/Desktop` のため）

```bash
find . ~/Desktop ~/Downloads -maxdepth 4 -name '*.pdf' -not -path '*/.book-summary/*' -print0 2>/dev/null | xargs -0 ls -t | head -20
```

新しいものから最大4件を AskUserQuestion の選択肢にする。各選択肢には、ファイル名を見出しにし、置き場所・ページ数・要約済みかどうか（作業ディレクトリに `summary.md` があるか）を説明に書く。要約が途中の本（`progress.md` はあるが完了していない）があれば、それを先頭に置いて「（続きから）」と添える。候補が見つからなければ、PDF のパスを尋ねる。

### 作業ディレクトリ
PDF と同じディレクトリに `.book-summary/<PDFのファイル名（拡張子なし）>/` を作り、そこを作業場所にする。

```
.book-summary/<書名>/
  pages/          … ページ画像（画像 PDF の場合）
  notes.md        … 章ノート（通読しながら追記）
  summary.md      … 要約本体（初稿 → 修正版）
  review-N.md     … N 回目のレビュー結果
  progress.md     … どこまで読んだか、レビューは何回目か
```

`progress.md` がすでにあれば、その続きから再開する。

### 文字データがあるか確認
```bash
pdftotext -f 1 -l 5 book.pdf - | head -50
```
- 意味の通る文章が出てくる → テキスト PDF。`pdftotext -layout` で章単位に抜き出して読む。
- 空、または文字化けする → 画像 PDF（Kindle のスクリーンショットなど）。ページを画像にして Read で読む。
  ```bash
  pdftoppm -png -r 100 -f <開始> -l <終了> book.pdf pages/p
  ```
  解像度は 100dpi あれば本文は読める。小さい図表が読めないときだけ、そのページを 150dpi で描き直す。

poppler（`pdftotext`、`pdftoppm`）がなくても、macOS なら kindle-capture スキルの `render_pages.swift` でページを画像にできる。PDFKit を使うので、追加のインストールは要らない。
```bash
swift ~/.claude/skills/kindle-capture/render_pages.swift book.pdf pages/ 1 2 3 ...
```
このスクリプトは解像度を指定できず、元のページの大きさのまま書き出す（`pages/page00001.png` のような名前になる）。文字データがあるかどうかは、1ページ目を画像にしたときに本文がスクリーンショット（Kindle のウィンドウ枠など）かどうかで判断する。どちらの方法も使えないときは、`brew install poppler` を勧める。インストールは環境を変える操作なので、自分では入れない。

### 目次を先に読む
最初の数ページから目次を探し、章の構成とページ範囲を `progress.md` に書く。この章立てが、ノートと要約の骨組みになる。

## 2. 通読して章ノートを作る

10〜15 ページずつ読み、読んだそばから `notes.md` に追記する。全部読んでからまとめようとすると、前半の内容がコンテキストから消えてしまうため。

章ごとに次の内容を残す。
- 主張・結論（著者が一番言いたいこと）
- 具体的な手順・条件・数値（例: 「25日線が上向き」「損切りは −5%」）
- その理由や根拠として挙げられていること
- 例外・注意点・やってはいけないこと
- 出典ページ（PDF のページ番号。本に印刷されたページ番号と違う場合は PDF 側に統一する）

**数値や条件はぼかさずに書く。** 「移動平均線を見る」では使えない。「5日線が25日線を上抜けたら」まで書く。本自体がぼかしている場合は、そう明記する（例: 「具体的な数値は示されていない」）。

1区切りごとに `progress.md` の「読了ページ」を更新する。

## 3. 要約の初稿を書く

`notes.md` から `summary.md` を書く。構成は次のとおり。

```markdown
# <書名>
- 著者:
- ページ数:
- 一言でいうと: （この本の核心を1〜2文で）

## 全体像
（本の主張と、章どうしのつながりを数段落で）

## 章ごとの要点
### 第1章 <章タイトル>（p.X–Y）
- 要点（p.X）
- ...

## 実践ポイント
（読者が実際にやることを、条件・手順・数値つきで箇条書き。1項目1行動。出典ページを付ける）
- [カテゴリ] 内容（p.X）

## 注意点・やってはいけないこと
- 内容（p.X）

## 本が答えていないこと・曖昧な点
（数値の根拠がない、条件が定義されていない、など。実践前に自分で検証すべき点）
```

**引用は最小限にし、自分の言葉で書く。** 長い文章の書き写しは著作権上の問題があるうえ、要点も見えにくくなる。原文が必要な定義や印象的な一文だけ、短く「」で引用してページを付ける。

「実践ポイント」が要約の価値の中心になる。本の内容から、読者がそのまま行動に移せる形に直す。ジャンルに合わせてカテゴリを決める（投資本なら「銘柄選定 / エントリー / 損切り / 利確 / 資金管理」など）。

## 4. 自律レビューで収束させる

初稿を書いた自分は、内容を知っているせいで抜けや誤りに気づきにくい。そこで、**要約を書いていないサブエージェントにレビューさせる**。

### レビューの回し方
1. Agent ツールで general-purpose のサブエージェントを起動する。プロンプトには `references/reviewer.md` の内容を使い、次の4つのパスを渡す。
   - PDF
   - `summary.md`
   - `notes.md`
   - 書き出し先の `review-N.md`
2. レビュー結果を読み、指摘ごとに次のどれかで対応する。
   - **直す**: 該当箇所を PDF で確かめてから `summary.md` を直す。
   - **退ける**: 指摘が誤っている場合は、理由を `review-N.md` の該当指摘に追記する。
3. 次の回のレビューでは、前回の `review-N.md` も渡す。退けた指摘が蒸し返されないようにし、直した箇所が本当に直っているかも確かめてもらうため。

### 終わる条件
次のどれかで終える。
- 「重大」と「中」の指摘が0件になった（「軽微」が残っていてもよい）
- 3回レビューした（上限）
- 前回と同じ指摘しか出なくなった（それ以上は進まない）

上限に達して未解決の指摘が残った場合は、`summary.md` の末尾に「未解決のレビュー指摘」として残す。黙って消さない。

## 5. 仕上げて出力する

### 出力先を提案する
完成した要約は、まず作業ディレクトリの `summary.md` に置く。そのうえで、保存先を AskUserQuestion で選んでもらう。おすすめを先頭に置き、「（おすすめ）」と添える。

選択肢を作る前に、使える保存先を調べる。
- **Notion**: Notion の MCP ツールが使えるなら、書名で検索して、同じ本のページ（読書記録のデータベースなど）があるか調べる。
  - ページがあれば「既存ページ『<タイトル>』に要約を追記」を選択肢にする。すでにある読書メモは消さず、末尾に「要約」の見出しで足す。
  - なければ「読書記録に新しいページを作成」を選択肢にする。読書記録のデータベースが見つからなければ、この選択肢は出さない。
- **ローカル**: 「PDF の隣に `<書名>-要約.md` として保存」。作業ディレクトリは隠しフォルダなので、見つけやすい場所にコピーする。
- **そのまま**: 「作業ディレクトリの `summary.md` のまま置いておく」。

同じ本のページが Notion にあれば、それがおすすめ。なければローカルをおすすめにする。ユーザーは「その他」から別の場所も指定できる。

Notion に書くときは、Markdown の見出しや箇条書きの構成をそのまま使う。書き込んだあとは、そのページの URL を報告に含める。

### ユーザーへの報告
次の内容を短く伝える。
- 一言でいうとどんな本か
- 実践ポイントの件数と、主なカテゴリ
- レビューを何回回したか、最後に残った指摘の要点
- 「本が答えていないこと」のうち、実践前に確かめるべき重要なもの
- 保存先（ファイルの絶対パス、または Notion ページの URL）

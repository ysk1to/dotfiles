# 要約レビュー用プロンプト

以下をサブエージェントへのプロンプトとして渡す。`{...}` の部分は実際の値に置き換える。

---

あなたは書籍要約のレビュアーです。要約を書いた人とは別人の立場で、この要約が「本を読んでいない人が、これだけを頼りに判断や実践をしても困らないか」を厳しく確かめてください。要約を書き直すのではなく、問題点を見つけて報告するのが役目です。

## 渡すもの
- 書籍 PDF: {PDFのパス}
- 要約: {summary.md のパス}
- 章ノート: {notes.md のパス}
- 前回までのレビュー: {review-1.md など。初回は「なし」}
- 結果の書き出し先: {review-N.md のパス}

PDF が画像だけの場合は、確かめたいページを画像にして Read で読んでください。出力先は作業ディレクトリの `pages/` にしてください。
- poppler がある場合: `pdftoppm -png -r 100 -f <p> -l <p> <PDF> <出力先>/p`
- ない場合（macOS）: `swift ~/.claude/skills/kindle-capture/render_pages.swift <PDF> <出力先> <p>...`

## 確かめること
1. **正確さ**: 要約の主張・数値・条件が、出典ページに本当に書いてあるか。少なくとも次のページを PDF で直接確かめる。
   - 実践ポイントの出典ページのうち、半分以上
   - 数値が出てくる項目はすべて
2. **抜け**: 目次の各章が要約に入っているか。本の中で強調されている重要な主張やルールが落ちていないか。ノートにはあるのに要約から消えた内容がないか。
3. **使える形か**: 実践ポイントが、条件・手順・数値まで具体的に書かれ、そのまま行動に移せる形になっているか。「〜を意識する」のような曖昧な書き方になっていないか。
4. **歪み**: 著者が条件つきで言っていることを無条件のように書いていないか。例外や注意点を落としていないか。要約者の意見が著者の主張のように混ざっていないか。
5. **引用**: 原文を長く書き写している箇所がないか（目安は1か所2文まで）。

## 前回のレビューがある場合
- 前回の指摘が直っているか確かめ、結果を書く。
- 要約者が理由を付けて退けた指摘は、その理由が明らかに誤っていない限り、もう一度出さない。

## 出力形式
{review-N.md のパス} に次の形式で書き出してください。最後の返答では、件数のまとめだけを返してください。

```markdown
# レビュー N 回目

## まとめ
- 重大: X件 / 中: Y件 / 軽微: Z件
- 前回指摘の解消: 解消 A件 / 未解消 B件（初回は省略）

## 指摘
### [重大] 短い見出し
- 該当箇所: 要約のどこか（見出しや項目）
- 問題: 何がおかしいか
- 根拠: PDF p.X にはこう書かれている、など
- 直し方の案:
```

重さの基準:
- **重大**: 内容が本と違う。または、読者が誤った行動をとるおそれがある（数値の誤り、条件の欠落、主要なルールの抜け）。
- **中**: 章や重要な論点の抜け、実践ポイントが曖昧で使えない、出典ページの誤り。
- **軽微**: 表現、構成、細かい補足。

問題が見つからなければ、無理に指摘を作らず「指摘なし」と書いてください。

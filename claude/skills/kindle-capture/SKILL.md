# Kindle の本を撮影して PDF にする

撮影はスキルと同じディレクトリにある `kindle-capture.sh` が行う。このスキルは、その前後の準備と確認を受け持つ。
スクリプトはすべて `~/.claude/skills/kindle-capture/` にあるので、どのディレクトリからでもこのパスで呼ぶ。
DRMの解除は行わない。撮影したPDFは個人で読む範囲にとどめる。

## 1. 事前チェック

```sh
~/.claude/skills/kindle-capture/preflight.sh "$TMPDIR/kindle-capture-preview.png"
```

Kindle を前面に出したりキー操作したりはしない。出力は key=value 形式。

| 出力 | 対応 |
|---|---|
| `kindle=not_running` | Kindle を起動して本を開くよう伝えて終了 |
| `window=none` | Kindle のウィンドウが見つからない。本を開いたウィンドウを表示するよう伝えて終了 |
| `window_onscreen=no` | 別のデスクトップにあるだけなら問題ない（撮影時に Kindle を前面に出す）。プレビューが真っ黒・空なら最小化されている可能性があるので、戻すよう伝えて終了 |
| `screen_recording=ng` | 「システム設定 → プライバシーとセキュリティ → 画面収録」で、Claude Code を動かしているターミナルアプリ（tmux の中なら、tmux を起動したターミナルアプリ）を許可し、アプリを再起動するよう伝えて終了 |
| `accessibility=ng` | 同じく「アクセシビリティ」を許可するよう伝えて終了 |

すべて問題なければ、`preview=` の画像を Read で見て次に進む。

## 2. プレビューから撮影の設定を決める

プレビュー画像から次を読み取る。

- **本が開いているか**: ライブラリ画面なら、本を開くよう伝えて終了。
- **現在のページ**: 下部の「Nページ中のMページ目」を見る。撮影は今のページから始まる。表紙や冒頭でなければ、そのまま始めてよいか、ユーザーが移動してから始めるかを確認する。ページは自分で動かさない。
- **見開き表示か**: 2ページが並んでいたら、「Aa」の表示設定で1列にするよう伝える。
- **ページ送りの方向**: 縦書きの日本語本は `-d left`、横書きの本は `-d right`。判断できなければ確認する。
- **書名**: 上部のツールバーか、本文ページ上部の見出しに表示されている書名を使う（表紙しか見えなければ表紙の文字から読む）。末尾の「…」や長い副題は取り除き、`/` と `:` は全角に置き換える。
- **出力先**: ユーザーが保存場所を指定していればそこに、なければ `~/Desktop` に `書名.pdf` で保存する。指定がディレクトリなら `<ディレクトリ>/書名.pdf`、ファイル名ならそのまま `-o` に渡す（相対パスは Claude Code を開いているディレクトリから解決される。拡張子がなければ `.pdf` が付く）。同名のファイルがあればスクリプトが末尾に日時を付けるので、上書きの心配はない。書名が読み取れなければディレクトリだけを渡す（`kindle_日時.pdf` になる）。
- **撮影範囲**: ページの本文が表示されている範囲だけを撮る。上部のツールバー、下部のページ番号やスライダー、隣のページのはみ出し、「○○に戻る」のサムネイルなどは範囲から外す。プレビューの画素座標を画面座標（ポイント）に変換して `-r` に渡す。
  - `scale` = `preview_pixels` の幅 ÷ `window` の幅（Retina なら 2）
  - `-r` = `window` の x + 左端の画素/scale, `window` の y + 上端の画素/scale, 幅の画素/scale, 高さの画素/scale（すべて整数に丸める）
  - 本文が欠けないよう、ページの境界から数ポイント外側を取る
  - 表紙だけを見て決めない。表紙（画像）と本文（文字）で表示の幅や高さが違うことがある。プレビューが表紙なら、まず `-n 3` で一時ディレクトリに試し撮りし、本文ページで範囲が合っているかを確かめる。試し撮りのあとは Kindle のページが進んでいるので、開始ページに戻してもらってから本番を撮る
  - 範囲を変えたら、プレビューを `sips -c <高さ> <幅> --cropOffset <上> <左>` で切り抜いて Read で見れば、Kindle を操作せずに確認できる

決めた設定（書名・出力先・方向・撮影範囲・開始ページ）を短くまとめ、AskUserQuestion で撮影を始めてよいか確認する。撮影中はマウスとキーボードに触れないよう、あわせて伝える。

## 3. 撮影

```sh
~/.claude/skills/kindle-capture/kindle-capture.sh -d <方向> -r <x,y,w,h> -o <出力先>
```

Bash の `run_in_background` で実行し、終了の通知を待つ（1ページあたり約1.5秒かかる）。待っている間は、ほかのアプリを前面に出すような操作をしない。

キー入力と撮影は前面のアプリに対して行われるため、撮影中はユーザーもほかのアプリを操作できない。裏にある Kindle は外から送ったキーやクリックを受け付けない（UIKit アプリのため）ので、作業しながら撮る方法はない。

- 終了コード 0: 完了。出力の「完了: <パス>（Nページ）」でパスを確認する
- 終了コード 2: ほかのアプリが前面に出たまま Kindle を戻せず、途中で止まった。「途中までのPDF: <パス>」に撮れたところまでが保存されている。その旨を伝え、Kindle を開始ページに戻して撮り直すことを提案する

ユーザーから中止を頼まれたら TaskStop で止める。途中までの画像は削除され、PDFは作られない。

## 4. 仕上がりの確認

出力の「完了: <パス>（Nページ）」を確認し、PDF の 1〜2ページ目、中ほどの1ページ、最後のページを PNG に書き出して Read で見る（Read で PDF を直接開くには poppler が必要なため）。

```sh
swift ~/.claude/skills/kindle-capture/render_pages.swift <PDF> "$TMPDIR" 1 2 <中ほど> last
```

- 本文が切れていないか、ツールバーなどが写り込んでいないか → 問題があれば `-r` を直して撮り直すことを提案する
- ページがめくり途中の状態で写っていないか → `-w 2` などで待ち時間を延ばして撮り直すことを提案する
- 最後のページが本の終わりか → 途中で止まっていれば、同じ画面（白紙など）が続いたため最終ページと判定された可能性を伝える
- 最後のページが Kindle の読了画面なら、確認せずに削除する。読了画面は本の中身ではなく、Kindle が最後に重ねて出す画面で、「Amazonでこの本をレビューしてください」と星の評価、「この本をおすすめします」、「著者をフォロー」、「シリーズの次巻」などが並ぶ（本によって一部の項目がないこともある）。本の中身（奥付、著作権表示、著者紹介、著書一覧など）は残す。

  ```sh
  swift ~/.claude/skills/kindle-capture/remove_pages.swift <PDF> last
  ```

  削除後に新しい最後のページを書き出して見直し、本の中身で終わっていることを確かめる。削除したことは報告に含める。

最後にプレビュー画像、書き出した PNG、試し撮りの PDF を削除し、出力先・ページ数・確認結果を報告する。
